# ESP32-BLETPMS-and-more

[English](Readme.md) | Русский

Прикладной TPMS-приёмник на трёх самостоятельных переиспользуемых библиотеках: NaBTools (Bluetooth), NaCBORUIforLVGL (CBOR-интерфейс) и NaWServer (HTTP/WS/SSE). Локальных копий библиотек в `lib` нет. См. [архитектуру](docs/architecture.md), [хранилище](docs/storage.md) и [происхождение исходников](PROVENANCE.md).

## Сборка

PlatformIO получает три библиотеки через ESP-IDF Component Manager по
закреплённым Git-коммитам. Первая сборка использует готовые веб- и CBOR-файлы
из репозитория. SDK 5.5.6 нужно заранее установить в каталог пакетов
PlatformIO под именем `framework-espidf-v5.5.6`.

```powershell
pio run -e s3-lcd7
```

Точные коммиты, настройка доступа к Git и команды генерации ресурсов приведены
в [описании зависимостей](docs/dependencies.md).

Профили: LCD7 800×480, `lilygo-t-display-s3` 320×170, `s3-headless` без дисплея. Физическая проверка одного профиля не подтверждает другую плату. Общая FS занимает последние 4 МиБ; перед прошивкой проверять реальный chip/MAC и текущую разметку. Не применять полное стирание или upload filesystem.

Wi-Fi хранит до восьми профилей в NVS через отдельную библиотеку [NaWFstore](lib/NaWFstore/README.md). Изменение без перепрошивки: `wifi help` в COM-консоли 115200 или страница `/setup` с существующим HTTP-входом. Кнопка `AP 5 min` на странице Settings включает временную точку доступа; её имя, пароль и URL показываются на локальном экране. Игнорируемый `src/modules/wifi/wifi_secret.hpp` (WIFI_SSID/WIFI_PASS и WIFI_ALT_SSID/WIFI_ALT_PASS) используется только для первичного заполнения отсутствующей конфигурации. Сохранённые профили, включая намеренно пустой список, имеют приоритет. Действующее подключение не прерывается ради поиска другой сети; BLE/UI не ждут сеть.

При первом запуске без сохранённых настроек импортируется приватный статический комплект из игнорируемого `src/modules/static_sensors_secret.hpp`. Пример без реальных кодов — `static_sensors.example.hpp`. Последующие обновления прошивки не заменяют сохранённый гараж этим комплектом.

## Экран и сайт

«Настройки» (`/#radio`) задают включение Wi-Fi сейчас и при старте, его сеанс 0..86400 секунд (0 — без ограничения), интервал и окно BLE. BLE работает постоянно; его выключателя или таймера сеанса нет. Интервал и окно задаются в миллисекундах, 5..10000 с шагом 5, окно не больше интервала. По умолчанию 80/80 мс — непрерывный приём; 80/40 мс задаёт окно 50%. SDK применяет новую пару с короткой остановкой/возобновлением сканера, сохраняя устройства и измерения. Сохранение транзакционное.

На LCD четвёртая CBOR-страница Settings позволяет включить Wi-Fi на 5 минут, выключить его, менять интервал/окно BLE и выбрать палитру. Пять схем — Светлая, Кремовая, Изумрудная, Тёмная, Ночная — используют механизм общих стилей Windows-демки NaCBORUIforLVGL, без пересоздания экранов. Прикладная палитра оставляет строки таблиц нейтральными; выбор кнопок и вкладок обозначается утолщённым внутренним контуром без изменения заливки и геометрии. В ночной схеме фон чёрный, все элементы выполнены оттенками красного: служебные элементы и единицы измерения темнее, числа давления ярче. На сайте в настройках есть отдельные кнопки схем экрана и сайта. Нижнее меню LCD оформлено выступающими вкладками с округлыми нижними углами. На плате без экрана не отключайте стартовый Wi-Fi без отдельного способа управления.

BLE остаётся пассивным, фильтр дубликатов выключен. Окно приёма не отменяет арбитраж общего радио с Wi-Fi; расширенный журнал позволяет сравнить участки с включённым и выключенным Wi-Fi.

Первая страница сайта — «Главная» (`/` или `/#home`). На ней тот же компактный блок сохранённой активной машины, что и в гараже: давление в колёсах, температура и секунды с последнего пакета. Схема здесь только для просмотра, без перестановки или снятия датчиков. Прежняя таблица TPMS и задачи приёмника сохранены в `/#tpms`. Выбор машины доступен на главной и в таблице; сохранённый выбор используется и после включения.

Основные страницы LCD через CBOR: TPMS, реклама TomTom со всеми полученными полями, общий скан BT. Время/IP сверху, меню снизу. Показания сохраняются при пропадании рекламы; справа от температуры идут секунды с последнего пакета. Не полученные с момента включения показания остаются неизвестными.

Сайт `http://<device-address>:80/`: те же разделы, файловый браузер, гараж и известные приборы. На телефоне то же боковое меню убирается в полоску 3 пикселя без иконок. Кнопка ☰ без рамки и свайп вправо от края открывают его; свайп влево, Escape, выбор раздела или нажатие вне меню закрывают. Отдельного мобильного выпадающего списка разделов нет. Сначала добавить найденный датчик в известные, затем выбрать/создать машину и назначить прибор каждому колесу. Можно менять число осей и колёс. Назначение выполняется явным выбором, с сохранением одной согласованной версии. Типы транспорта отделены от назначения колёсам; рабочего 433-МГц приёмника эта версия не добавляет.

Сохранён прежний HTTP Basic-вход `1` / `1` для страниц, HTTP API и SSE. WS имеет прежнее поведение без этого HTTP middleware; команды изменения настроек через WS не принимаются. `/ws`, `/events`, `/index`, `/index2` сохранены. `/api/state` и `/api/state.cbor` — текущие показания; `/api/research` — реклама; `/api/settings` — настройки; `/api/files` и `/api/file` — чтение файлов. Подробный контракт FS и ограничения — [storage.md](docs/storage.md).

Журнал поездки — `tpms.diag.0` и `tpms.diag.1`, до 128 КиБ каждый, до шести часов после включения. Он различает принятый raw-пакет, разбор, допуск в известные и измерение. Можно скачать через «Файлы» после поездки. Чужие файлы не стираются и FS не форматируется.

Проверки устройства:

```powershell
node tools/check-device.mjs http://<device-address>:80
node tools/check-settings.mjs http://<device-address>:80
```

Вторая проверка создаёт временную машину с существующим прибором, проверяет запрет ручного изменения датчиков и выдуманных обнаружений, поиск, транзакции/назначения/конфликты и восстанавливает исходный гараж; ревизия при этом увеличивается. Фактический RF-приём и физическое качество дисплея проверяются отдельно. Результаты — [verification.md](docs/verification.md).

`src/ui/project.json` — полный документ интерфейса; кодек создаёт CBOR. `tools/generate-ui.mjs` — явное пересоздание текущего макета, а не обязательный шаг при ручном редактировании JSON. Web-исходники — shell-head.html, app.js, tpms-sensor.js, sensor-ui.js и CSS; build-web.mjs объединяет их с локальным tooltip-модулем для встраивания. Сгенерированные кириллические шрифты и их лицензии находятся в src/ui/fonts и docs.

У известного датчика нет редактируемого названия: только системный ID и внутренний ID протокола. Транспорт/протокол приходят из скомпилированного каталога драйверов; один `APP_TPMS_BLE_TOMTOM` включает и драйвер, и доступное значение BLE/TomTom. Запись добавляется из реально разобранного обнаружения кнопкой «Наш»; произвольный ввод идентичности запрещён. Схема настроек 2 автоматически сохраняет прежние ID и весь гараж при переносе версии 1.

Поиск запускается до изменения давления. Компонент датчика в виде шины показывает протокол, транспорт, номер, последнее давление и давность; при накопленном изменении от базы на 0,10 bar меняет цвет до сброса поиска. Его можно перетащить на колесо либо выбрать датчик и затем колесо касаниями. Назначения сохраняются кнопкой «Сохранить» машины. Обнаружение не угадывает положение по мощности сигнала.

В гараже пул слева, машина справа. Перенос между занятыми местами меняет датчики местами; свободное место принимает датчик, освобождая прежнее. У приборов есть свободные текстовые теги: значок бирки открывает редактор, теги вводятся через запятую. Это любые собственные отметки, без заданного перечня; теги и ID сохраняются при перестановке между колёсами.

Машина показана сверху: ↑ обозначает перед, оси идут сверху вниз, одно место по центру, парные — группами у краёв. Подписей позиций и обязательных подсказок на схеме нет. Звезда в списке машин выбирает машину для включения; у редактируемой машины одновременно сохраняются её правки. Остальные названия и точная геометрия доступны в явном редакторе.


## Оформление кода и лицензии

Использовать Uncrustify 0.83.0_f с корневым `uncrustify.cfg`.
`uncrustify-check.cmd` проверяет оформление, `uncrustify-apply.cmd` форматирует
отслеживаемые C/C++ файлы. Архивный `Example`, сторонние компоненты и
сгенерированные шрифты/assets исключены.
[Правила владельца](agents/code_style.ru.md) общие с тремя библиотеками.

Самостоятельно написанный код — [MIT](LICENSE). Сторонние и адаптированные
материалы сохраняют свои условия и notices: [области лицензий](LICENSES.md),
[происхождение](PROVENANCE.md). В своих исходниках используются краткие SPDX-шапки.
